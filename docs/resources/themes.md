# Themes

A theme is one plain CSS file in `client/themes/`, copied by webpack to `public/themes/` and loaded after `css/style.css` through the `<link id="theme">` in `index.html`. Picking a theme in Settings → Appearance rewrites that link's `href` to `themes/<name>.css` (`client/js/settings.ts`); `js/loading-error-handlers.js` does the same from localStorage before the app boots so there is no flash of the wrong theme. There is no preprocessing: a theme's rules simply cascade over the base stylesheet, and the user's custom stylesheet (Settings → Appearance) cascades over the theme.

`style.css` declares its palette as custom properties on `:root` (`--body-color`, `--window-bg-color`, `--link-color`, `--highlight-bg-color`, the `--tok-*` code colours, …) and reads them everywhere it can, so most of a theme is a `:root` block. Where the base stylesheet still has literal colours (the sidebar rows and badges, header icons, the input and the context menu, message-type icons, the mIRC colour table) a theme restates those selectors.

The list the Settings dropdown shows is static, in `client/js/configuration.ts` (`themes`, with a `displayName` and an optional `themeColor` for the browser chrome), and `defaultTheme` there is what a fresh browser gets; a deploy overrides that with `theme` in `config.json` (`docs/resources/branding.md`). A stored theme name the build no longer has falls back to the default at boot (`boot.ts`), which is how browsers that had `default` stored came over to `coffee`.

**To add a theme:** drop `client/themes/<name>.css` in, add its entry to `themes` in `configuration.ts`, and add the name to the list in `test/tests/build.ts`. Start from `creama.css` or `cobalt.css` for another colour direction on the same rules (tokens only), from `morning.css` for a theme on TheLounge's variables.

## The handoff themes

`coffee` and `creama` implement the warm direction of the colour redesign handed off in `docs/resources/themes/` (`README.md`, `ink-amber-theme.md` and the `ink-amber-*.png` mockups); `cobalt` and `frost` implement the cool one, `cobalt-frost-theme.md` with its own mockups. The handoff is colour only, and so are the themes: layout, spacing and type are untouched, and its suggestions beyond colour (a `data-theme` switch, sweeping the components for literal colours, hover/focus/mention states) were deliberately left for later — except the composer's focus ring, which is in: the bar is flush with the window, so `#form:focus-within` draws it as the top edge (accent border plus a 2px inset of `--focus-ring`) and the caret takes the accent (`caret-color`), in `coffee.css` and, through the import, the three token-only themes; `style.css` gives `day` and `morning` the same in their green.

The two directions share every rule. `coffee.css` is the one file with selectors in it; `creama.css`, `cobalt.css` and `frost.css` are token values alone, so a fifth direction is one more `:root` block and costs nothing in bundle size beyond its own colours. The handoff intended exactly that — both directions use the same token names, "so they are drop-in interchangeable".

The custom properties use the handoff's token names (`--chat-bg`, `--rail-accent`, …) so a value can be checked against its tables, plus a few the handoff does not have: the tints (`--tint-soft`/`--tint-strong`, translucent overlays that must be light on a dark surface and dark on a light one), the notice-box pairs (`--note-*`, `--warn-*`, `--error-*`, `--ok-*`), `--menu-bg`, and the message semantics (`--event-join`, `--event-quit`, `--nick-default`, `--notice-color`, `--action-color`). TheLounge's own variables are mapped onto the tokens at the end of `:root`, which is what keeps the rest of `style.css` in step.

Deviations from the handoff, all for contrast (`docs/projects/accessibility.md`), are listed in the header comment of each file, and both light variants needed the same ones: muted text, the link colour, the join green and the placeholder tone are darker than specified because the handoff's own light values missed its 4.5:1 rule (`frost` moves the link blue `#1f6feb` → `#2166e0` and the muted grey `#6b7a8c` → `#65727f`); `coffee`'s footer icons use the light rail's muted tone. Nick colours are the biggest addition: the handoff gives three per variant, `style.css` hashes nicks into 32 slots (`.user.color-1`…`-32`), so each theme carries a generated 32-colour palette — hues swept around the wheel at one oklch lightness and the chroma both directions agree on (0.115), every slot ≥ 4.6:1 on a dark chat surface or ≥ 5:1 on a light one, so a nick still reads on a highlighted row.

The rail gradient is on `body` as well as `#sidebar`, so the gutter `day.css` keeps around the window continues the sidebar instead of stopping at its edge; the two gradients coincide because both span the viewport.

## The `<3` theme

`heart.css` is coffee's rules with its own tokens and three things no other theme has. **Fonts**: Nunito 400 (with an italic face) and 800, and Baloo 2 700, ship beside it under `themes/heart/` (fetched once by `tools/heart/fetch-fonts.mjs`, OFL texts alongside) — the bundled woff2 files are the Latin subset, so other scripts fall back to the system stack mid-line. **Motion**: every `.msg` fades in on insertion, pending copies included — the entrance animations use `backwards` fill (never `both`), so a pending copy settles at the existing pending style's dimmed opacity once its fade ends, rather than the animation's own end state pinning it — the sidebar rows, header and composer rise on load, a mention glows, and glitter bursts are pseudo-element backgrounds on an own message's pending copy, a hovered row, and a reaction chip's arrival (never a persistent class, or the burst would replay on every redraw) — four bursts cycled by `:nth-child`. **The meadow**: background layers on the scroll container of a channel or query (`#chat .chat-view[data-type="channel"] .chat` and its query twin) — sky, hills, ground, clouds — sized from `--strip` and varied by the conversation's seed, which `Chat.vue` publishes as `data-scene` (0–5) and `--channel-seed` (0–1) from `helpers/channelSeed.ts` (FNV-1a of the lower-cased name; queries too, the lobby not); the hue is computed on `#chat-container`, where the seed is, since a bare `:root` never sees an inline style; over the hills at the foot of the chat, muted text and the darkest nick slots fall below 4.5:1 (3.6 and 4.0 on the ground band) — the text halo is the mitigation, and the trade-off is accepted. The animals, and a rainbow arc that fades in for two of the six scenes, are plan 2 — both need a pseudo-element slot this plan does not add. Chromium runs all three animation forms — SMIL attributes, CSS-in-SVG, and SMIL path morphs — in a background image (`tools/heart/spike-svg-background/`); Firefox and Safari are still to be checked there. `test/themes/heart.ts` checks the tokens, the 32-slot nick palette's contrast, and that each section is present; `tools/scenarios/theme-heart.mjs` checks the rest in a browser (`SEANCE_IRC_PORT` points it at another ircd's port, default 8067).

## Checking a theme

`yarn test` never loads a stylesheet. Build, serve `public/`, and look (`docs/resources/browser-testing.md`); the Appearance dropdown switches live. `tools/scenarios/themes.mjs` drives that dropdown through every theme against the dev ircd, checks the stylesheet link, the stored name and the browser chrome colour, measures the pairs above on the four handoff themes (text, timestamps, links, the join line, a nick on a highlighted row at ≥ 4.5:1; icons and the placeholder at ≥ 3:1) from computed styles, and leaves a screenshot of the chat under each theme.
